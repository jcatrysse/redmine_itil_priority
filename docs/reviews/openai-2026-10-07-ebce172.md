Major, app/views/issues/_itil_priority.html.erb:~120
The JS builds priorityNames from IssuePriority.active only. If the matrix points to a now-inactive priority id, showPriority looks it up in priorityNames and renders an empty label, hiding the current/computed priority for users without the override permission.
Scenario: An admin deactivates “High” priority after it was used in the matrix (settings still store its id). A helpdesk user (no override) opens an existing linked issue whose matrix maps to the deactivated id. On load, syncPriority runs and showPriority sets the display to '', so the priority appears blank.
Fix: Build priorityNames from all defined priorities, not only active, e.g. replace IssuePriority.active with IssuePriority.all (or IssuePriority.order(:position) without the active scope). Additionally, defensively fall back to the server-rendered @issue.priority when a name isn’t found.

Resolution: fixed in the next commit ("Review: priority display knows inactive priorities"): priorityNames now holds every priority, and an unknown id keeps the text already shown instead of blanking it, for users with and without the override (the override path used the select's active options and blanked the same way). Test: test_form_knows_the_names_of_inactive_priorities (fails without the fix); issue_form.mjs and settings.mjs re-run, 0 problems.
